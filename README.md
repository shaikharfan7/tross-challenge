# LinkedIn Profile API

A reverse-engineered API for retrieving structured LinkedIn profile data.

Built as part of an engineering challenge focused on reverse engineering HTTP APIs, data extraction, API design, and deployment.

## Overview

The API accepts a LinkedIn profile URL and returns the profile information available through the underlying LinkedIn endpoints as structured JSON.

The initial implementation focuses on the fields required by the challenge:

* Name
* Headline
* Location
* About
* Experience
* Education
* Skills
* Certifications
* Languages
* Profile images

Additional fields may be exposed as the underlying responses are explored and verified.

The implementation communicates directly with LinkedIn over HTTP. It does **not** use browser automation, Playwright, Puppeteer, Selenium, or a headless browser.

## Reverse Engineering

The LinkedIn integration is based on inspecting the HTTP traffic generated by LinkedIn and identifying the requests responsible for retrieving profile information.

The implementation then reproduces the relevant requests directly from the backend and maps the resulting data into a stable application-level schema.

This approach keeps the upstream protocol details isolated from the public API and makes changes to the LinkedIn integration easier to reason about.

## Configuration

Authentication/session information is supplied through environment variables.

Sensitive values are never stored in the repository.

The repository contains an `.env.example` file showing the required configuration without exposing any actual credentials.

## Error Handling

The API handles common failure cases including:

* Invalid profile URLs
* Invalid request payloads
* Profile not found
* Authentication/session failures
* Upstream request failures
* Rate limiting
* Unexpected upstream responses
* Missing profile fields

Errors are returned as structured JSON with appropriate HTTP status codes.

## Security

The API validates incoming LinkedIn profile URLs and does not act as a generic HTTP proxy.

Credentials and session information are kept outside source control and should be provided through environment variables or deployment secrets.

The implementation does not attempt to bypass authentication, CAPTCHAs, access controls, rate limits, or other security mechanisms.

## Deployment

The API is designed to be deployed as a standalone Node.js service and exposed publicly over HTTPS, as required by the challenge.

Docker is included to keep the runtime environment reproducible.

The deployed endpoint will be added here once deployment is complete.

## Known Limitations

This project depends on undocumented LinkedIn endpoints, so the upstream behavior is not guaranteed to remain stable.

In particular:

* Endpoints and response formats may change.
* Authentication/session requirements may change.
* Some profile fields may not be available for every account.
* Profile visibility can affect the returned data.
* Rate limiting may affect requests.
* Profile images and other assets may not always be available.

The API therefore treats upstream data as optional where appropriate rather than assuming every profile contains every field.
